## 2. 지금 내 상태 (레포 기준)

- **할 줄 아는 것**: BufferedReader 입출력, 스택/큐/덱, 1차원 DP, 순열·조합·백트래킹 (N과M, 14889, 15661, 10971)
- **구멍**:
  - 2차원 격자 구현 (14500 테트로미노가 unsolved에 있다)
  - 격자 BFS/DFS (1260을 아직 커밋하지 않았다)
  - 시뮬레이션은 풀어본 적이 없다
  - 마지막 커밋이 2025-09-01이라 1년 넘게 쉬었다 → 손을 다시 푸는 게 1순위
- **실수할 위험이 큰 것**:
  - 파일마다 `package solved;` 줄이 있다 → 제출하면 컴파일 에러가 난다
  - static 변수를 즐겨 쓴다 (`static int min = MAX_VALUE`) → SWEA처럼 테스트케이스가 여러 개면 **TC마다 초기화를 안 해서 틀리는** 버그가 제일 흔하다

> 결론: 새 알고리즘은 공부하지 않는다. **2차원 배열 + 델타 탐색 + BFS + 시뮬레이션**만 판다.

## 4. 시험 당일 진행

1. **처음 5분**: 문제를 끝까지 읽고 입력 범위에 밑줄 친다 → 시간 복잡도를 정한다
   - N ≤ 10 → 완전탐색 / 순열 OK
   - N ≤ 1,000 → O(N²) OK
   - N ≤ 100,000 → O(N log N)까지
2. **종이에 설계**: 방향 배열, 종료 조건, 예외 케이스를 적은 다음에 코딩한다
3. **1번을 확실하게**: 2번으로 넘어가려면 1번을 맞혀야 한다는 후기가 있다. 1번에 시간을 충분히 쓴다
4. 2번이 막히면 완전탐색으로라도 답을 낸다 (부분점수가 있는지는 확인된 적 없다)

### 제출 직전 체크리스트
- [ ] `package` 줄을 지웠고 클래스명이 맞는가 (SWEA는 `Solution`)
- [ ] `System.setIn(...)` 줄을 주석 처리했는가
- [ ] **TC마다 static 변수와 배열을 초기화**하는가 (min, max, cnt, visited)
- [ ] 출력 형식이 `#1 답`인가 (`#` 뒤 번호, 공백 1개, 줄바꿈)
- [ ] 합이나 곱이 int 범위(약 21억)를 넘을 수 있으면 `long`을 썼는가
- [ ] 예제 말고 직접 만든 케이스를 2~3개 돌려봤는가: N=1, 최대 크기, 전부 0 / 전부 같은 값
